# REQ-082 — Ten Default Themes Pack

> **Status:** pending · **Captured:** 2026-09-26 · **Layer:** themes/*
> **Source:** deep documentation pass — features named in docs/01–09 that had no request yet

## Request

A fresh installation must ship with ten genuinely different themes.

- corporate, tech, agency, portfolio, magazine, commerce, documentation, startup, minimal, government.
- Each theme: its own layout (not a colour-swapped clone), own component set, own typography scale.
- Per-theme dark/light mode, responsive strategy, hero treatment, card system, blog design, menu structure.
- Sample content per theme so the preview looks real during selection.
- Visual regression snapshots per theme (the QA harness renders every theme).

## Implementation spec

### Scope (in / out)

**In**

- Ten themes in `themes/<key>/` for the canonical keys of docs/03-FRONTEND.md: `corporate`, `tech`, `agency`, `portfolio`, `magazine`, `commerce`, `documentation`, `startup`, `minimal`, `government`. `minimal` ships today and becomes the reference implementation of the contract; the other nine are new and each declares a manifest, a layout set, tokens, sample content and preview assets.
- Per theme, all of it owned by the theme: light and dark token sets, a modular type scale, a spacing rhythm, a container and grid strategy, a header variant, a footer variant, a hero treatment, a card system, a list/index design, a detail design, motion budget and default colour mode. One shared section library (REQ-083) supplies the primitives; a theme composes them and may replace any of them with its own renderer.
- Layout coverage per theme: home, content page, index/list (blog, news, portfolio, products, docs, tickets as applicable), detail (post, product, documentation page), search results, tag/category, 404 and a `style-guide` slot that renders the theme's tokens, type scale, buttons, cards, forms and states on one page (used by QA, the gallery and the builder).
- Sample content per theme under `themes/<key>/sample/`: `site.json`, `menu.json`, `pages.json`, `posts.json`, `products.json` (commerce), `docs.json` (documentation), `media/*` (small local images, licensed for redistribution) and `settings.json`. The preview route and the gallery render the sample scene on an empty site so selection is honest, and the sample set can be installed into a real site on request.
- Preview assets per theme: `themes/<key>/preview/{light,dark}.png` plus `screenshots/home-{390,1440}.png`, generated by `scripts/theme-previews.mjs` from the sample scene, committed, hash-stable, and consumed by the gallery (REQ-075) and the marketplace listing format (REQ-048).
- Distinctness as a test, not an opinion: `scripts/theme-distinctness.cjs` extracts a signature per theme — type scale ratio, base size, spacing base, radius, container width, grid, header variant, hero variant, card variant, list variant, motion budget, accent hue — and fails when two themes share more than a documented overlap budget. It also fails when two themes' accent hues sit within a small delta of each other.
- Visual regression: `scripts/qa/visual.cjs` renders the sample scene per theme × viewport (390 / 768 / 1440) × mode (light / dark) and diffs against baselines in `docs/qa/baselines/themes/<key>/<viewport>-<mode>.png`; run records and findings land in the quality tables (REQ-085). Baseline updates need an explicit flag and produce a reviewable diff summary.
- Renderer integration: an unknown or invalid theme key falls back to `minimal` (already the case), only the active theme's stylesheet and fonts are loaded for a visitor, and the ten keys are listed once in the renderer registry and in the onboarding bundle so a fresh install can pick any of them on the first-run screen.
- Accessibility and responsiveness are part of each theme's definition of done: skip link, landmarks, focus-visible styles, tap targets ≥ 44px, mobile navigation pattern (sheet, drawer or bottom bar), breakpoint behaviour for every section, `dir="rtl"` smoke check, and a contrast pass on the theme's own token pairs (REQ-085 gates it).

**Out**

- The theme engine, manifest schema, settings surface, activation and preview flow (REQ-062), the gallery UI (REQ-075), the builder (REQ-076), the section library itself (REQ-083) and the SDK, packaging and CLI (REQ-084). A contract gap found while building a theme is fixed in those requests, never by a theme inventing a private path.
- Marketplace distribution, third-party themes, paid themes and ratings (REQ-048).
- Business logic inside a theme: a commerce theme does not implement checkout, pricing rules or cart storage (REQ-008 owns those) and a documentation theme does not implement search (REQ-002 / REQ-019).
- Full RTL localisation of the sample content and translated sample copy beyond English plus one non-Latin smoke locale (REQ-020 owns localisation).
- A theme-per-customer product: these ten are the defaults, not a custom-design service.

| commerce | 12-col, 1440px max | 1.200, neutral UI stack | merchandising band + category tiles | product card with price, badge, quick action | top bar + category menu + cart affordance | light |
| documentation | 3-column (nav/content/toc), 1440px | 1.200, text-first, high legibility | none: search-first landing | dense list and cards, code blocks | persistent sidebar tree + search + version picker | light |
| startup | 12-col, 1160px | 1.250, rounded geometric | centred headline + product band | rounded, illustration-led | top bar + CTA emphasised | light |

- **Preview route (renderer)** — the same page components the live site uses, driven by the sample scene: home, one index page, one detail page, search, 404 and `style-guide`, with mode and viewport switched from the preview bar (REQ-062 owns the surrounding frame).
- **Sample scene content** must look real: named posts with authors and dates, products with prices and short descriptions, documentation pages with a version label, navigation that matches the pages, and images sized for their slots. No lorem ipsum, no repeated filler headline, no real company names or logos.
- **States** — listing skeletons per theme (card-shaped, not generic bars), empty state when a list has no items, a page with a single item, a detail page with missing media, a very long headline and a long navigation list (stress fixtures), 404, and an error page. Sample scenes include at least one stress page so the states are visible in preview and in snapshots.
- **Keyboard** — visible skip link per theme, logical focus order through header → main → footer, mobile navigation closes on `Esc` and returns focus, search is reachable by keyboard, mega menus open with `Enter`/`Space` and close with `Esc`.
- **Mobile** — per-theme navigation pattern above, card grids collapse to one column with preserved aspect ratios, sticky CTAs do not cover content, tables (pricing, comparison) become stacked rows, typography scales down one step, tap targets ≥ 44px, no horizontal scroll at 390px.

### API

| Method | Path | Purpose | Permission |
|---|---|---|---|
| GET | `/api/v1/themes` | Bundled and installed themes with manifest data, modes, preview assets and active flag | `themes.read` |
| GET | `/api/v1/themes/{key}` | One theme: manifest, layout inventory, sample-content availability, preview asset hashes | `themes.read` |
| GET | `/api/v1/themes/{key}/sample-content` | The theme's sample scene (bundled themes only) | `themes.read` |
| POST | `/api/v1/sites/{site_id}/sample-content` | Install a theme's sample pages into a site (dry-run report, refuses to overwrite existing slugs, marks the rows so one action removes them) | `content.pages.create` |
| DELETE | `/api/v1/sites/{site_id}/sample-content` | Remove the sample pages this request installed | `content.pages.delete` |
| POST | `/api/v1/sites/{site_id}/theme` | Activate a theme for the site, keeping the previous choice for rollback (REQ-062) | `themes.activate` |
| GET | `/api/v1/public/themes/{key}/preview` | Renderer preview payload: sample scene or site content, mode and viewport hints | none (public, site-scoped, rate-limited) |
| GET | `/api/v1/themes/{key}/snapshots` | Latest visual-snapshot summary per theme (viewport × mode, diff ratio) | `quality.read` |

Read and activation endpoints are REQ-062's design and are listed here for completeness; this request adds the sample-content and snapshot rows. `themes.*` and `quality.*` keys are added to `crates/permissions/src/catalogue.rs`; sample-content installation is a content operation and is therefore guarded by content permissions rather than theme ones.

### Data model

- Bundled themes need no table of their own: a theme is files in `themes/<key>/` plus the manifest the registry reads (`crates/onboarding` already carries the bundled list), and `sites.theme` (migration `0007_onboarding.sql`) stores the active key with a format constraint. This request extends the bundled list from one key to ten.
- Sample previews are static files served with an ETag; no caching table, because the scene is deterministic and small.
- Migration `0016_theme_sample_content.sql` (next free number at merge; other requests also add migrations, so numbering follows merge order):
  - `alter table pages add column sample_theme text null` with `check (sample_theme is null or sample_theme ~ '^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$')`, plus `create index pages_sample_theme_idx on pages (site_id, sample_theme) where sample_theme is not null`.
  - Sample installation writes normal `pages` and `page_revisions` rows (so publishing, revisions and the block editor all work on them) with `sample_theme = <key>`; `DELETE` removes exactly those rows and refuses when a sample page has been edited since installation (the comparison is a revision count and an updated_at stamp).
- Visual baselines live in the repository under `docs/qa/baselines/themes/<key>/`; run metadata and diffs are rows in REQ-085's quality tables with `kind = 'visual'` and `theme = <key>`, so there is one history, not two.
- Asset budgets are enforced by the harness rather than stored: theme CSS ≤ 40 KiB unminified-equivalent threshold, self-hosted fonts ≤ 2 files and 120 KiB total, sample images ≤ 250 KiB per file and ≤ 2 MiB per theme, no third-party requests at render time.
- Fonts are versioned with the theme under `themes/<key>/assets/fonts/` with a licence file; a theme without a recorded licence fails the gate.

### Events

- `theme.sample_content.installed` — a sample scene was installed into a site (payload: site, theme key, page count, dry-run flag).
- `theme.sample_content.removed` — the sample rows were removed (payload: site, theme key, page count).
- `theme.preview.generated` — the preview-asset job wrote new images for a theme (payload: theme key, hash summary); consumed by CI and by anyone mirroring previews.
- `theme.visual.regressed` — a snapshot diff exceeded its budget (payload: theme key, viewport, mode, diff ratio, artifact link); this is the one automation may act on, and it is recorded through the quality gate tables as well.
- Activation itself is a site change and emits the theme activation event owned by REQ-062; this request does not duplicate it.

### Acceptance criteria

- [ ] All ten theme directories exist with a valid manifest, a `package.json` workspace entry, styles, layout set and sample content, and the renderer resolves every one of the ten keys.
- [ ] `scripts/theme-distinctness.cjs` passes: no two themes share more than the documented overlap budget, and no two accent hues sit within the minimum delta.
- [ ] Each theme renders home, one index page, one detail page, search, 404 and `style-guide` from its own sample scene, in light and dark, at 390 / 768 / 1440.
- [ ] Contrast of every declared text pair passes in both modes (REQ-085's contrast test runs over all ten token sets).
- [ ] Preview assets are committed for every theme in both modes, hash-stable across two consecutive generation runs, and the gallery (REQ-075) shows them with name, version, modes and an active badge.
- [ ] Sample scenes read as real content: named posts/products/docs with dates, authors, prices or versions, correct images per slot, and no filler text or real-company branding.
- [ ] `POST /api/v1/sites/{site_id}/sample-content` reports what it would create, refuses to overwrite an existing slug, and `DELETE` removes exactly the installed rows; a page edited after installation is refused with the reason.
- [ ] Only the active theme's stylesheet and fonts load on a live site: the network trace for a page shows no assets of the other nine themes.
- [ ] A visitor with no JavaScript still gets the sample and live pages rendered (server-rendered markup), with progressive enhancement limited to navigation and search.
- [ ] Mobile navigation patterns work per theme: sheet, drawer or bottom bar opens, traps focus, closes on `Esc`, returns focus, and never hides the primary action behind a scroll trap.
- [ ] Keyboard pass per theme on home + one inner page: skip link first, visible focus everywhere, no focus loss on navigation, mega menu and search operable without a pointer.
- [ ] Stress fixtures render without overflow: a 140-character headline, 12 top-level navigation items, a card grid with one item, and a detail page without media.
- [ ] `dir="rtl"` smoke check renders each theme's home and one inner page with correct mirroring of layout order and no clipped text.
- [ ] Theme asset budgets hold: CSS, fonts and images within the limits above, and no third-party network request at render time.
- [ ] `scripts/qa/visual.cjs` produces baselines for all ten themes × 3 viewports × 2 modes, and a deliberate one-pixel-shift fixture fails the diff with an artifact.
- [ ] A snapshot diff over budget emits `theme.visual.regressed` and appears on `/quality` with a link to the diff image.
- [ ] The onboarding first-run list and the renderer registry both offer the ten keys; an unknown key falls back to `minimal` with a logged warning rather than a broken page.
- [ ] `scripts/qa/run.sh` walks the sample preview of every theme and reports zero high findings; the walkthrough inventory lists all ten preview routes.

### QA plan

- **Walkthrough must click:** the gallery (REQ-075) card for each theme → preview; mode toggle light/dark; viewport toggles 390/768/1440; page switcher across home, index, detail, search, 404 and `style-guide`; open mobile navigation and close it; activate one theme, then roll back; install and remove sample content on a scratch site and read the report.
- **Visual check should see:** ten silhouettes that are obviously different at a glance (type, grid, hero, card density), sample content that looks like a real site rather than a template, consistent spacing rhythm inside each theme, dark mode that is a designed mode rather than an inverted one, no clipped text, no overlapping sticky elements, and stable layout during load (no visible shift).

### Risks / notes

- Snapshot noise is the fastest way to kill a visual gate: sample scenes must be deterministic (fixed content, animations disabled during capture, fonts loaded before capture, real-time or rotating elements masked) and only one browser is the baseline. Document that.
- Distinctness thresholds are a proxy for taste; pair them with a short human checklist per theme (hero, typography, cards, motion) so the gate catches clones without punishing consistency.
- Themes are presentation only: no data fetching beyond the public payload, no site-specific assumptions, and every theme must degrade visibly with empty or partial data (missing product price, untitled page, empty documentation tree).
- Only the active theme's assets may ship to a visitor; loading all ten stylesheets would make the "free themes" feature cost every page load.
- Fonts must be self-hosted, subset and prefixed with `font-display: swap`, with the licence recorded; a third-party font request fails the gate.
- Sample content must be fictional: invented brands, no real logos, no real people, images licensed for redistribution and credited in a `CREDITS` file per theme.
- Ten themes multiply maintenance: sections come from one library (REQ-083) and components from one kit (REQ-081), so a fix lands once; a theme that forks a component must justify it in its README.
- Older installations may reference keys that changed names; keep the manifest `aliases` field and the `minimal` fallback so a rename never blanks a live site.
